2 · Excludes1 vs. Excludes2

NoteMeaning
Excludes1 — NOT CODED HEREGenerally do not report the excluded code with the code above the note. Exception: when the two conditions are unrelated, both may be used if supported. Clarify unclear relationships.
Excludes2 — NOT INCLUDED HEREThe excluded condition is not part of the first code. Both may be assigned when both are present and reporting rules permit.

Student reminder: Check the actual Tabular List note and its context; don't use an Excludes1 rule without assessing whether the conditions truly are unrelated.

3 · Common instructions

Code first: sequence the underlying condition first when applicable. Use additional code: add the specified code when required for additional detail. Code also: two codes may be required; the note itself does not determine sequence.

4 · Combination codes and the “with” convention

Look for a combination code that fully identifies the condition and complication or manifestation. When the Alphabetic Index lists two conditions under “with” or “in,” the relationship may be presumed unless documentation clearly says they are unrelated or a chapter-specific rule requires explicit linkage. Relevant examples include certain diabetes complications and hypertension with CKD. Do not extend this convention to arbitrary conditions. Verify the Tabular List and sequencing instructions.

5 · Code selection versus diagnosis reporting

A valid code is not automatically reportable. Consider whether documentation and encounter/setting rules support reporting it. In outpatient settings, “rule out,” “probable,” or “suspected” conditions are not coded as established; use supported symptoms, findings, or reasons for the visit, as appropriate. Inpatient discharge guidelines for qualifying uncertain diagnoses differ.

6 · Practice checkpoints

  1. “Rule out pneumonia” at an outpatient visit: do not assign confirmed pneumonia; use supported symptoms or reason for visit.
  2. Diabetes plus a complication listed under “with”: check Index linkage, combination code, documentation and applicable additional-code rules.
  3. A condition appears only on the problem list: determine whether encounter reporting criteria are met; don't automatically code it solely because it is listed.
